# Gallery 派生缓存生命周期闭环

## 已确认范围

- 有效 CARD_480 / STATIC_POSTER 不受容量 LRU 淘汰；MISSING、UNREADABLE、Excluded、来源失联本身不授权删除基础缓存。
- 新当前基础图发布后，旧内容和已替换 Profile 的派生资源可以回收；新基础图未就绪时保留旧文件，但 HARD_INVALID 仍不得服务。
- 显式忘记 Item、替换缺失身份和删除 Gallery 时，数据库级删除触发器在同一事务写入清理 outbox。文件删除失败、崩溃或重启不丢失待办。
- 孤儿巡检仅处理 cache/items 的严格生成命名、已登记 GalleryItem UUID、普通单硬链接文件；未知文件、符号链接、用户媒体、Manifest、Coser 资料不在权限范围。孤儿至少保留 24 小时，正在生成的同身份任务继续保护。
- 后台 Operations 提供只读预览、有效／失效／待清理／孤儿容量摘要、部分巡检提示和显式选择清理。手动清理要求密码及 CLEAN；执行复核数据库引用、任务和文件身份，过期选择拒绝。
- 自动清理每分钟有界推进，孤儿按持久游标轮转；文件删除使用目录描述符及 no-follow，不能经链接越界。清理失败保存稳定错误码并重试，不在默认日志输出路径。

## 实现细节与使用方式

- 现有启动／每分钟缓存调度先执行生命周期维护，再执行增强缓存容量 LRU。每轮旧派生记录、删除待办、孤儿各最多100项；孤儿仅走一个UUID前缀分片，目录遍历最多10000节点／2秒，未完成时持久化词典序游标，下轮继续。完整分片轮转可能跨越数小时，不承诺删除后立即归零。
- 删除派生记录与outbox先原子提交，再用短写事务复核引用／未结束生成任务并删除单个文件。即使文件已删而最终确认提交失败，也不会恢复悬空可服务记录。文件删除失败退避15分钟；同路径重新发布会在发布事务中撤销旧待办。
- 文件删除先以目录描述符定位并验证inode、大小、mtime、单链接，再以不覆盖方式改名到同目录`.gc-`隔离名复核后unlink；中断的隔离文件仍可恢复清理。只尝试移除已空的Profile／revision／Item目录，不递归删除任何目录。
- 后台管理 → 运维 → Gallery派生缓存清理，点击预览后选择待清理项，重新输入所有者密码与`CLEAN`；最多选择100项。预览最多200候选／5秒，不修改数据库游标或文件，执行重新生成预览并核对所有选择ID，陈旧选择要求重新预览，不自动重试。
- 引用／失效／待删除容量来自数据库记录；孤儿容量只是本次有界巡检观察值，并非磁盘完整清点。失效容量包含新基础图未就绪而必须保留的旧资源，不等于当前可回收容量。前台与后台帮助均提示部分巡检和失败待办。
- REST只返回不含路径的候选标识／原因／字节数／稳定错误码；认证、Same-Origin、维护模式、密码及确认词门禁沿用现有产品边界。手动操作审计仅存聚合计数和错误码，自动清理日志同样不泄露路径。
