# 迁移测试问题与改进备忘录（2026-09-23）

> 适用范围：CGM 1.5 Linux／Docker 可移植迁移实机测试
>
> 本文记录实机迁移中确认的问题、既有行为和后续改进边界。未标记为“已实现”的条目均不得视为当前产品能力。

## MT-01：有效目录 Manifest 无法进入全自动导入链路

状态：源码已实现并通过定向回归，尚未提交、迁移正式业务库或部署。

### 实测场景

- 新系统中不存在且未预留 `.cosplay.json` 内的 Gallery `set_id`。
- 媒体目录具有有效、内容完备的 `.cosplay.json`。
- 媒体库已配置自动化策略，用户执行“扫描并自动处理”。

### 当前行为

- 发现阶段能够读取 Manifest，并将目录识别为 `MANIFEST` 候选。
- 目录型 Manifest 候选的 `autoCreate` 当前固定为 `false`，所以自动化运行不会创建 DRAFT。
- 用户必须在最新发现结果中手动点击“创建 Draft”；Manifest Pull、来源扫描和后续自动激活才可能继续。
- 存档型来源在启用“自动导入存档”后不受此项限制。

这不是 Manifest UUID 冲突，而是目录型 Manifest 候选当前采用的保守导入策略。它会阻断“媒体与 Manifest 已迁移到新机器、目标库为空、通过媒体库自动化重建”的预期流程。

### 确认的优化目标

媒体库处于 `TRUSTED` 自动化模式时，目录型有效 Manifest 应允许进入自动创建 DRAFT 和后续自动激活链路，但必须同时满足：

1. Manifest 格式、`set_id`、引用关系及安全边界校验通过；
2. Gallery、Item、External Link 及核心实体 UUID 不存在不可接受的占用、待认领或退役冲突；
3. 来源位于当前已启用媒体库边界内，且不存在重复来源或待人工确认的来源改绑；
4. 来源扫描完整、安全且未超过限制；
5. 自动激活继续遵守内容分级、可展示媒体、派生资源和其他既有激活门禁；
6. 任一条件失败时保留候选并显示稳定、可操作的问题码，不生成替代 UUID，不覆盖既有身份，也不静默跳过。

`MANUAL`和`ASSISTED`模式保持现有人工确认语义。是否将此能力作为独立策略开关，留待实现设计阶段结合媒体库自动化页面一并确认。

### 验收基线

- 全新空库、未占用 UUID、有效目录 Manifest：一次可信自动化运行可以创建 DRAFT、Pull Manifest、扫描媒体，并在派生任务及激活门禁完成后激活。
- 相同场景使用 `MANUAL`或`ASSISTED`：仍停留在明确的人工复核入口。
- UUID 冲突、重复来源、无效 Manifest、越界路径、不安全扫描和超限来源：均不得自动创建或自动激活。
- 自动化中断后可按现有持久化运行语义恢复，不重复创建 Gallery 或身份。
- 不改变 Manifest 的 `set_id`，不把冲突自动解释为新 Gallery。

## 方案复核结论（2026-09-26）

已确认把后续修复拆成两个相互隔离但共享身份校验器的功能：

1. 迁移工作台接管当前有效 Manifest，认领迁移会话已预留的 UUID，并重建可安全验证的 Gallery；
2. 媒体库发现界面复核 Manifest 身份冲突，只在用户明确选择后导入或分叉为独立 Gallery。

方案总体可行，但不能通过删除待认领身份、忽略 UUID 冲突或直接放宽 `CLEAN` 判断实现。现有迁移包的身份账本、Gallery 索引和磁盘 Manifest 分别承担身份、来源定位和业务内容职责；两个新功能必须保留这三层边界。

实现预计需要产品数据库前向迁移，用于保存接管证据以及候选身份问题的稳定分类。优先考虑同一个纯新增 schema 版本：旧会话和旧候选默认无接管／无问题码，不改写既有 Gallery、Manifest 或 UUID。迁移包 format v2 继续可读，不以升级包格式作为修复旧包的前置条件。

## MT-00：迁移包拆分为两个显式档位

状态：源码已实现并通过包格式、导入与Web回归，尚未提交或部署。

### 复核结论

迁移功能拆为两个由用户在导出前明确选择、导入后不可互相误判的档位：

1. **核心目录包（`CORE_CATALOG`）**：只迁移 Coser、Work、Character、Tag、SocialAccount、核心实体 Alias／Tombstone、Slug Redirect、Tag 层级以及被引用的 Coser 原始头像／Banner；保留这些核心实体自身的 Portable UUID，不包含 Gallery、GalleryItem、ExternalLink 身份、Gallery 索引、媒体库定位或 owner continuity。
2. **Gallery 身份辅助包（`GALLERY_IDENTITY_ASSISTED`）**：包含完整核心目录包，再包含 Gallery／Item／Link 身份声明、`gallery-index` 和用户明确选择的 owner continuity；继续沿用 MT-02 的迁移工作台接管／重建和 MT-03 的媒体库冲突复核策略。

核心目录包的导出、检查和导入不得读取 Gallery Manifest 状态作为成功门禁。即使源库存在 `DB_DIRTY`、`MISSING`、损坏 Manifest 或无法定位的 Gallery，只要核心实体及 Coser 资源本身有效，核心目录包仍应独立完成。导入完成后不创建媒体库映射、不预留 Gallery 局部 UUID、不生成 Gallery 重建项目，也不显示“应用 owner continuity”。

核心目录包并不是“无 UUID 包”。Manifest 对 Coser／Work／Character／Tag 的引用和核心实体合并历史仍依赖其 UUID；只有 Gallery、GalleryItem、ExternalLink 范围从该档位移除。Alias 和 Tombstone 继续永久保留，不提供释放或重新认领退役 UUID 的操作。

### 格式与兼容策略

现有 format v1/v2 固定要求 `identity-ledger.json`、`core-catalog.json` 和 `gallery-index.json`，并没有可判定的档位字段。首版不应通过写入空 Gallery 索引、把计数置零或根据文件缺失来猜测档位，否则旧导入器可能把包误判为完整 Gallery 辅助包。

建议新增向前格式版本并在 `package.json` 中加入必填枚举 `profile`：

- `CORE_CATALOG` 的 required payload 不包含 `gallery-index.json` 和 `owner-continuity.json`；身份账本只允许核心实体类型；
- `GALLERY_IDENTITY_ASSISTED` 继续要求 Gallery 索引，并允许可选 owner continuity；
- 现有 format v1/v2 在新导入器中统一解释为 `GALLERY_IDENTITY_ASSISTED_LEGACY`，继续执行既有严格校验和后续接管修复；
- 新格式包不得被旧版本静默降级读取，应明确报告格式不受支持；导出界面应同时显示档位、格式版本和包含范围。

两个档位共享核心目录序列化、校验、冲突审核和 Coser 资源导入实现，避免出现两套核心实体合并语义。Gallery 辅助能力作为额外负载和后续阶段叠加，不能反向成为核心目录事务的一部分。

### 档位选择与边界

- 默认推荐跨机器日常迁移使用核心目录包，由媒体及 `.cosplay.json` 在目标机通过媒体库发现和 MT-03 重建 Gallery。
- 需要核对源机 Gallery 清单、保留 Gallery／Item／Link 身份生命周期、检测漏拷贝来源或应用可选 owner continuity 时，选择 Gallery 身份辅助包。
- Gallery 辅助包仍不是完整数据库备份；任务、审计、认证、缓存、浏览历史和机器路径不进入包。
- 完整同机灾难恢复继续使用完整备份，不能用任一可移植档位替代。
- Gallery 辅助包允许按既有“允许不完整 Gallery 声明”策略导出，但必须把异常逐项保留在索引和报告中；异常 Gallery 不应阻断已就绪 Gallery 的部分重建，也不得伪装成已完整迁移。

### 潜在问题及控制

- **用户选错档位**：导出确认页以人类可读摘要列出是否包含 Gallery 身份、定位清单和个人状态；包导入后不允许通过开关改变档位。
- **同一核心目录重复导入**：继续按 UUID、revision 和显式冲突决策幂等处理，不能因档位不同重复创建实体。
- **先导入核心包、后导入辅助包**：Gallery 辅助包必须允许复用完全一致的既有核心身份；核心内容不同仍进入现有 Merge 复核，不能跳过。
- **核心包导入后扫描到 Manifest UUID**：普通媒体库流程不得假设这些 Gallery UUID 曾被迁移；按 MT-03 的 `UNCLAIMED`／冲突分类处理。
- **退役 Gallery 局部 UUID 不在核心包中**：目标机无法从核心包获知其历史，发现 Manifest 时只能依赖本机注册表判断；需要跨机保留此类否决历史时必须选择 Gallery 身份辅助包。

### 验收基线

- 同一业务库在 Gallery Manifest 全部异常时，核心目录包仍可导出、检查和导入，核心实体数量、UUID、关系、Alias／Tombstone及资源一致。
- 核心目录包导入后不存在媒体库映射、Gallery Claim、Gallery 重建或 owner continuity 待办。
- Gallery 身份辅助包保持 format v1/v2 的兼容读取，并能进入 MT-02／MT-03 后续流程。
- 两个档位重复导入相同核心目录均幂等；任何核心身份冲突都不能因使用核心档位而降低校验等级。
- 包检查、Web 工作台、审计和错误码都明确携带档位，不通过缺失文件或 Gallery 数量推断。

## MT-02：迁移工作台接管当前 Manifest 并认领 UUID

状态：核心闭环源码已实现并通过回归，尚未提交、迁移正式业务库或部署。

### 目标场景

- 迁移包已完成核心目录导入并预留 Gallery、Item、External Link UUID；
- 包内某个 Gallery 的 Manifest 状态为 `DB_DIRTY`、`MISSING`，或目标文件已在导出后发生受控变化；
- 目标媒体根中现有 Manifest 内容完整、可解析，且用户明确选择以当前文件作为重建依据；
- 不修改迁移 ZIP，也不要求重新打包原始媒体。

### 建议交互

- 重建表格继续显示包内状态、当前预检状态和稳定问题码；只有可接管的问题显示“复核当前 Manifest”。
- Gallery 身份辅助包在媒体库映射完成后提供迁移级选项“自动接管唯一的完全匹配来源”，默认关闭；开启时先显示预计自动接管、仅重建 DRAFT、可请求自动激活及仍需人工复核的数量，要求所有者重新认证和精确确认词 `AUTO ADOPT`。
- “安全重建后自动激活”是独立选项，不能随自动接管隐式开启。只有包内 owner lifecycle 明确请求恢复 ACTIVE、用户在本次迁移中显式授权，或目标媒体库采用 `TRUSTED` 自动化策略时，才具备请求自动激活的授权来源；授权也不能绕过当前环境的激活门禁。
- 先执行只读预览，显示将接管的 Gallery 数、声明的 Item／Link 数、缺失声明、额外声明及阻断原因，不显示 Manifest 正文或不必要的绝对路径。
- 支持单项和有上限的批量选择；提交要求所有者重新认证及精确确认词 `ADOPT`。
- 接管成功只保存新的校验证据，不创建 Gallery、不认领 UUID；随后再次预检，正式重建时才按既有事务逐项认领身份。
- Manifest 在预览、确认或重建之间发生变化时，证据立即失效并返回稳定问题码，用户必须重新复核。

### 自动接管唯一完全匹配来源

自动接管只用于减少 Gallery 根在目标媒体库内整体移动后的逐项确认，不是放宽 Manifest 内容接管或 UUID 冲突策略。每个自动接管项必须同时满足：

1. 迁移包档位为 `GALLERY_IDENTITY_ASSISTED`，用户已在当前迁移会话显式开启自动接管；旧 format v1/v2 可使用该选项，但仍按旧包身份归属限制校验；
2. 导出记录的原相对位置不可用，所有已启用且映射到本会话的目标媒体库中只发现一个相同 `set_id` 候选；
3. 候选 Manifest 的原始字节哈希、revision、schema、`set_id`和来源类型与包内记录完全一致，不使用规范化后相等、字段子集相等或业务内容近似匹配替代；
4. Gallery、Item、External Link 的 `ACTIVE + PENDING` Claim 与 Manifest 声明完整闭合，同一 UUID 未出现在其他 Gallery、其他候选、其他会话、Registry 占用、Alias 或 Tombstone 中；
5. 核心实体引用已经导入并可解析，Character→Work 等关系一致；
6. 来源位于目标媒体库边界内，完整扫描安全、未超限，Manifest 的每个成员相对路径唯一命中实际媒体；
7. 最近完整发现快照、Manifest 哈希、媒体库映射和 UUID 状态在执行前重新校验且未变化；
8. 不存在另一个当前可访问的相同 `set_id` 来源。不能因为另一个副本位于原相对位置、不同映射库或未被当前列表展开而忽略它。

满足条件后，系统可以自动保存来源解析证据、认领 Gallery／Item／Link UUID、创建 DRAFT、扫描成员并 Pull Manifest。派生资源和其他后台工作继续使用既有持久化队列；“自动完成”表示流程可在后台继续推进，不承诺在同一个 HTTP 请求或页面会话内同步完成。

自动激活必须另行满足以下条件：

- 本次迁移具有前述明确的自动激活授权来源；
- Gallery 当前仍为此次重建产生的可恢复 DRAFT，没有用户并发修改或新的复核问题；
- 内容分级、可展示媒体、核心关系、媒体处理及所有既有激活门禁在目标环境重新通过；
- 门禁暂时等待派生任务时显示持久化进度，任务完成后重试；硬阻断时保留 DRAFT 和稳定问题码，不回滚已经安全认领的身份，也不反复闪跳页面。

任一自动接管条件不成立时只把该项降级为人工复核，不影响其他合格项继续处理；不得退回路径近似匹配、按名称匹配、自动分叉或重新生成 UUID。

### Gallery 相对来源变化的重新定位

`gallery-index` 保存的是导出时 Gallery 相对于逻辑媒体库根的 `relative_source`。它能吸收目标机媒体库绝对根变化，但不能吸收库内层级变化。例如旧来源 `CoserA/Set01` 在目标库变成 `Imported/CoserA/Set01` 时，当前实现只检查“新根 + 旧相对路径”，会错误停留在 `PORTABLE_SOURCE_UNAVAILABLE`。

Gallery 身份辅助包必须增加独立的逐 Gallery“目标来源解析”步骤，把导出相对路径视为定位提示和审计证据，而不是不可修改的目标路径：

1. 完成逻辑媒体库映射后，在对应目标媒体库的最近一次完整发现快照中查找有效 Manifest；不得接受越过媒体库边界的任意路径输入；
2. 先尝试原相对位置。若存在且身份匹配，标为 `EXACT`；
3. 原位置不存在时，按 `set_id` 查找本会话全部已映射目标库内的候选。只有一个安全候选时标为 `RELOCATED_UNIQUE`；迁移级自动接管关闭或其他自动门禁不成立时等待用户确认，全部自动门禁成立时可生成自动接管证据；多个候选标为 `DUPLICATE_ACCESSIBLE_SOURCE`，不得自动选主；没有候选则保持 `UNRESOLVED`；
4. 候选 Manifest 的哈希、revision 与包内记录完全一致时，可按“来源重新定位”确认；内容已变化时必须进入 MT-02 的 `ADOPT` 预览，不能把路径移动同时解释为内容接管；
5. 首版只允许来源类型保持一致。目录与存档相互转换可能改变成员路径及 sidecar 语义，应交由媒体库身份复核或外部整理，不在迁移工作台自动转换；
6. 保存“导出相对来源”和“目标已解析相对来源”两个字段。重建、扫描和来源创建只使用后者；审计记录旧／新相对定位及 Manifest 哈希，不记录不必要的绝对路径；
7. 用户确认使用发现快照令牌和当前 Manifest 哈希；正式重建前重新校验媒体库仍启用、候选仍在库内、`set_id`／类型／哈希未变且 UUID Claim 未被其他操作占用。

路径重新定位只解决 Gallery 根整体移动。如果 Gallery 内部媒体相对路径也改变，仍会触发 Item 路径集合不一致；这不能由来源改绑自动修复，必须先更新并复核 Manifest，随后按 MT-02 接管，或在 MT-03 中作为独立副本显式导入／分叉。

### 接管门禁

每个接管项必须同时满足：

1. 迁移会话处于已映射、尚可继续重建的状态，Gallery 尚未重建；
2. 逻辑媒体库已映射到启用的本机媒体库，来源路径没有逃逸、符号链接或类型错配；
3. Manifest 格式、大小、`set_id`、revision、路径和集合约束有效；
4. 来源扫描完整、安全、未超限，Manifest 中每个成员路径精确命中一个实际成员；
5. Gallery、Item 和 External Link UUID 均为该迁移会话对应类型的 `ACTIVE + PENDING` 声明，或已由同一重建幂等认领；Alias、Tombstone、其他会话预留和跨类型占用一律阻断；
6. 同一个 UUID 在本轮全部接管 Manifest 中只能出现一次，不能跨 Gallery 重复认领；
7. 核心实体引用必须能按已导入目录解析，Character→Work 等关系不得冲突；
8. 接管时保存当前 Manifest 的 SHA-256、revision、schema、接管时间和原包状态／哈希，正式重建前全部复验。

### 旧 format v1/v2 包的身份归属限制

现有迁移包的身份账本是扁平 UUID 集合：它能证明某个 Gallery／Item／Link UUID 属于本次导出，但没有独立保存“某个 Item／Link 原先属于哪个 Gallery”的成员关系；原本由导出时的精确 Manifest 哈希间接固定该关系。

因此接管旧包时，系统无法证明当前 Manifest 中的 Item 在源机导出瞬间属于同一 Gallery。接管操作的准确语义必须是：

> 用户明确指定“目标机当前有效 Manifest 是新的权威 Gallery—Item／Link 关联证据”，系统只证明其中每个 UUID 来自本迁移会话且在当前接管集合内唯一。

只读预览和确认弹窗必须说明这一点。若要求严格还原源机导出瞬间的历史归属，仍只能修复源机状态、重新 Push 并重新导出。未来可评估在新包格式中增加每个 Gallery 的成员身份摘要，但不得以此取消旧 format v1/v2 的显式修复能力。

### 声明集合不一致

- 当前 Manifest 出现迁移包未声明的新 Gallery 局部 UUID：首版接管阻断，不在迁移重建中临时生成或普通注册；用户应重新导出，或在迁移流程之外走媒体库身份复核。
- 包中仍有 `ACTIVE` Item／Link 声明未被任何当前 Manifest 使用：首版接管阻断。系统不能猜测这些身份已删除，也不能把它们静默 Tombstone。
- 多个待接管 Gallery 存在时，应对会话内全部当前 Manifest 做集合覆盖与唯一性检查。允许分批保存接管证据，但只有声明闭合后会话才能最终进入 `GALLERIES_REBUILT`。

### 部分重建与会话状态

现有执行入口只要预检存在一个阻断项就拒绝整批重建。为使“重建有效 Manifest”有实际意义，后续应允许只处理本次预检中仍为 `READY` 的项：

- 已重建项保持幂等，不因其他项失败回滚；
- 阻断项保留声明、问题码和继续处理入口；
- 会话在全部 `ACTIVE` 声明被安全认领或按未来明确策略解决前，保持未完成状态；
- 可选 owner continuity 仍只能在会话完整重建后应用，不得对部分 Gallery 提前应用；
- 重试不得重复创建 Gallery、Item、任务或注册表身份。

### 潜在问题及控制

- **TOCTOU**：预览后文件变化。以接管哈希作为不可变执行令牌，重建前重新读取并比较。
- **过期包掩盖数据丢失**：`DB_DIRTY` 可能代表源数据库有未 Push 修改。界面必须提示当前文件将成为权威内容，不能把接管描述为无损恢复源数据库。
- **`MISSING` 含义不唯一**：它也可能只是导出时没有同步记录，并不证明文件当时不存在；预览应展示包状态，不推断原因。
- **路径映射错误**：继续复用媒体库边界、来源类型和安全扫描校验，不允许用户直接填写任意 Manifest 路径。
- **同一身份多处出现**：`set_id`相同且存在多个可访问候选时始终进入重复来源复核；即使其中一个与旧相对路径相同，也不得静默忽略其他副本。
- **发现快照过期**：目标相对来源不是永久授权。媒体库重新扫描或文件移动后必须使旧解析令牌失效，并重新定位。
- **超大媒体库重新定位成本**：复用完整发现快照中已解析的 Manifest 身份索引，不为每个重建项重复遍历媒体库；最终执行仍逐项读取和安全校验真实文件。
- **用户误解自动激活**：自动接管默认只保证安全重建至 DRAFT；UI 分开显示“接管身份”和“请求自动激活”，并逐项展示门禁结果。
- **后台任务中断**：自动流程使用既有持久化状态和幂等阶段游标，重启后从安全边界继续；不得通过前端轮询重新提交接管或制造页面闪跳。
- **声明永久预留**：接管失败不得删除或释放声明；修复接管证据后可重试。需要单独设计会话终止语义时再评审，不能顺带增加“释放 UUID”。
- **审计与隐私**：记录 import ID、set ID、数量、旧／新哈希和稳定结果码；默认日志不记录标题、人物名称、Manifest 正文或物理路径。

### 验收基线

- `DB_DIRTY`和无同步记录的`MISSING` Gallery，在当前 Manifest 与声明完全闭合时可预览、确认、重新预检并重建；包本身字节不变。
- 未确认接管的异常项继续阻断；确认后文件发生变化重新阻断。
- UUID 缺失、额外、跨类型、退役、跨 Gallery 重复或属于其他会话时均拒绝接管。
- READY 项可先重建，BLOCKED 项保留并可恢复；未闭合会话不能应用 owner continuity。
- 中断发生在证据保存、Gallery 创建、来源扫描、Manifest Pull 或身份认领任一边界时，重复执行均收敛到同一结果。
- 仅媒体库绝对根变化且相对来源不变时保持现有直接映射；Gallery 根在库内整体移动时可从完整发现快照提出唯一候选，经显式确认后重建。
- 开启自动接管时，唯一且字节级完全匹配、Claim 闭合的迁移来源可无需逐项确认完成身份认领和 DRAFT 重建；关闭选项时相同候选保持人工确认行为。
- 自动激活未单独授权时流程稳定停在 DRAFT；已授权但激活门禁未通过时保留 DRAFT、进度和稳定问题码，不把接管失败与激活阻断混为一类。
- 相同`set_id`存在多个可访问位置、来源类型变化、候选越界、快照过期或 Gallery 内部成员路径变化时不得自动重新定位。

## MT-03：媒体库 Manifest 身份冲突复核与人工显式导入

状态：源码已实现并通过身份、显式导入、分叉与并发证据回归，尚未提交或部署。

### 目标

媒体库发现有效 Manifest 后，在创建 DRAFT 前集中识别 UUID 状态。无冲突候选继续提供人工“导入为 DRAFT”；有冲突候选不进入自动化，由用户根据冲突类型执行来源改绑、返回迁移工作台、分叉副本或外部修复。

### 身份分类与允许操作

| 分类 | 含义 | 允许操作 |
| --- | --- | --- |
| `UNCLAIMED` | Gallery 及局部 UUID 均可安全注册 | 人工导入为 DRAFT；MT-01 实现后，TRUSTED 模式可自动导入 |
| `SAME_GALLERY_SOURCE_MOVE` | `set_id`属于已有 Gallery，原来源不可用 | 人工确认来源改绑，保留全部 UUID |
| `DUPLICATE_ACCESSIBLE_SOURCE` | 同一`set_id`的新旧来源都可访问 | 人工保留现有来源、确认改绑，或把副本分叉为新 Gallery |
| `PENDING_PORTABLE_CLAIM` | UUID 已由未完成迁移会话预留 | 禁止普通导入和分叉，提供直达对应迁移工作台的入口 |
| `UUID_KIND_CONFLICT` | UUID 已被其他实体类型占用 | 硬阻断；不得复用或自动改号 |
| `UUID_RETIRED` | UUID 是 Alias 或 Tombstone | 硬阻断；不得复活 |
| `LOCAL_ITEM_OR_LINK_CONFLICT` | Item／Link UUID 已属于其他 Gallery／对象 | 阻断普通导入；只有确认整个来源是独立副本且其他门禁通过时才允许整体分叉 |
| `CORE_REFERENCE_REVIEW` | 核心实体同 UUID 的类型、名称提示或关系不一致 | 先人工复用／映射／修复实体引用，不能通过 Gallery 局部 UUID 分叉掩盖 |

单个问题候选不得阻断同一媒体库中其他无冲突候选的发现或处理。自动化只统计并保留“需要身份复核”，不得静默跳过、覆盖或自动生成替代 UUID。

### 人工显式导入顺序

完整 Manifest 可能包含既有 `item_uuid`。当前普通候选流程在来源扫描前尝试 Pull，尚未创建 GalleryItem 时可能无法应用完整 `items[]`。实施时必须调整为可恢复的确定顺序：

1. 提交前重新读取候选、Manifest 哈希、媒体库和全局 UUID 状态，验证预览令牌未过期；
2. 注册 Gallery `set_id`，创建 DRAFT 和唯一 Source；
3. 安全扫描来源，并按 Manifest 的精确相对路径注册／认领未占用的 `item_uuid`，而不是先生成另一套 Item UUID；
4. 扫描成功后 Pull Gallery 业务元数据、顺序、排除项、封面和链接；
5. 任一步失败都保留明确的可恢复 DRAFT／来源问题状态，不返回“失败但实际已创建”的模糊结果；重复执行不得创建第二个 Gallery；
6. 显式导入只创建 DRAFT，不绕过内容分级、可展示媒体和关系等激活门禁。后续是否自动激活仍由已保存的媒体库自动化策略决定。

### 独立副本分叉

分叉严格沿用开发备忘录第 10.3 节，只有用户确认两份来源应成为两个独立 Gallery 时才可执行：

- 生成新的 Gallery `set_id`、全部 `item_uuid`和全部`link_uuid`；
- 同步改写封面 Item、排除项及其他 Gallery 局部 UUID 引用；
- 保留 Coser、Work、Character、Tag 等共享核心实体 UUID 和业务内容；
- 新 Manifest 使用新的身份谱系和更新时间，revision 起点在实现前固定并覆盖测试；
- 不复制、移动、删除或改写任何媒体文件；DIRECTORY 改写根内 Manifest，ARCHIVE 只改写相邻 Manifest，永不重打包归档；
- 媒体库必须允许元数据写回，目标父目录实际可写，原 Manifest 在确认时哈希不变；使用现有原子写和单一 `.bak` 机制。

文件系统写入与 SQLite 事务不能形成真正的跨资源原子事务。推荐把“分叉写回”和“导入 DRAFT”拆成两个可恢复动作：先原子写出新的自洽 Manifest，再重新发现并由用户显式导入。这样数据库导入失败时，新 Manifest 仍是可重试的有效独立身份，不需要冒险回滚媒体目录文件。只读来源不提供分叉按钮，用户须在系统外复制并修正后重新扫描。

### 不应提供的操作

- 不提供无条件“重新生成所有 UUID”按钮；
- 不把路径变化误判为新 Gallery；
- 不允许普通媒体库流程接管迁移会话的 Pending Claim；
- 不释放、删除或改写 Alias／Tombstone；
- 不因 Gallery 局部身份分叉而自动复制或重建核心实体；
- 不在未完成身份预览时自动激活。

### UI 与并发复核

- Libraries 最新发现列表显示身份分类、影响的 UUID 类型、稳定问题码和建议入口；技术详情默认折叠。
- 高影响的改绑与分叉使用只读预览、Manifest 哈希／候选快照令牌、所有者重新认证和精确确认词。
- 提交时重新检查候选仍来自最近完整发现快照、来源仍在同一媒体库、Manifest 哈希未变、UUID 状态未变且没有新的自动化运行占用该来源。
- 分叉成功后旧候选标记为已解决并要求重新发现，不在旧快照上直接创建 DRAFT。
- 审计仅保存候选技术 ID、操作类型、UUID 数量及稳定结果码，不记录业务名称、Manifest 正文或默认日志路径。

### 验收基线

- 无占用的完整 Manifest 能显式导入，保留 Gallery／Item／Link UUID，并按“扫描后 Pull”顺序形成可恢复 DRAFT。
- 同一 Gallery 路径迁移只改绑；两个可访问副本必须二次确认，绝不自动选主。
- Pending Claim 候选能准确跳转到所属迁移会话，不能被普通导入抢占。
- 分叉后 Gallery／Item／Link UUID 全部更新，封面和排除引用自洽，核心实体 UUID 不变，原始媒体字节不变。
- Manifest、候选、媒体库或 UUID 在预览后变化时提交拒绝；只读来源、越界路径、不安全扫描和超限来源不能分叉或导入。
- 单个冲突不影响其他候选继续导入／自动处理，所有失败都有可操作问题码。

## 源码落实结果（2026-09-26）

- 产品数据库升至schema v17，只新增迁移档位、来源解析／接管证据、自动接管授权和发现候选身份证据字段；v16数据不被改写，迁移幂等测试已覆盖。

- 建立`internal/manifestidentity`纯只读共享检查器，媒体库发现与迁移重建共用UUID种类／状态、核心引用和来源解析语义；发现快照持久化Manifest schema、revision、字节哈希、分类、问题码和执行令牌。
- 无冲突Manifest人工导入已改为“创建DRAFT/Source→按相对路径注册Manifest Item UUID并扫描→Pull业务数据”，并允许已创建DRAFT后的幂等续跑；Manifest或发现证据变化会拒绝执行。
- 媒体库界面显示稳定身份分类；待迁移Claim可直达迁移工作台，已有Gallery来源移动沿用显式改绑；确认独立副本时可把Gallery／Item／Link UUID整体分叉，Cover和排除引用同步改写，核心实体UUID和媒体字节不变，写回使用原子文件和单一`.bak`。
- 迁移预检可从已映射媒体库的最近完整发现快照按`set_id`解析`EXACT`、`RELOCATED_UNIQUE`、`DUPLICATE_ACCESSIBLE_SOURCE`和`UNRESOLVED`，同时保留导出位置与目标位置。唯一来源可逐项接管当前Manifest；预览令牌、文件哈希或Claim变化会使证据失效。
- 重建不再因一个BLOCKED项拒绝全部READY项；已完成项幂等保留，异常项继续保存问题码，会话只有在全部ACTIVE声明闭合后才完成，owner continuity仍不得提前应用。
- 工作台提供默认关闭的自动接管和独立自动激活选项，并要求所有者密码与精确确认词`AUTO ADOPT`。自动接管只处理唯一且原始字节哈希完全相同的来源；自动激活只会把重建DRAFT交给目标媒体库已保存的`TRUSTED + autoActivate`持久化队列，仍执行派生资源、分级和全部既有激活门禁，否则稳定保留DRAFT。
- `TRUSTED`媒体库自动化现在允许身份分类为`UNCLAIMED`的有效目录Manifest自动创建DRAFT；`MANUAL/ASSISTED`仍要求人工导入。待迁移Claim、跨类型、退役、局部Item/Link、核心引用或重复来源问题均关闭自动创建。
- 本轮不释放Alias/Tombstone，不自动改号，不修改迁移ZIP，不重新打包Archive，不复制或删除媒体，不扩大owner-continuity范围。

## 依赖驱动的实施顺序（2026-09-26 重新评估）

实施不按本文 MT 编号或章节先后推进，而按“先证明判定逻辑、再持久化、先人工闭环、后自动化”的依赖关系推进：

1. **冻结跨模块契约并补齐特征测试**：先定义包档位、Manifest 身份分类、来源解析状态、稳定问题码、预览令牌和确认语义；用现有 format v1/v2、发现候选、迁移重建和扫描流程的特征测试固定兼容边界。本阶段不改变运行行为，也不先承诺数据库字段布局。
2. **实现纯只读共享身份检查器与来源解析器**：统一解析 Gallery／Item／Link、核心实体引用、Registry／Claim／Alias／Tombstone 状态，并在完整发现快照上计算`EXACT`、`RELOCATED_UNIQUE`、`DUPLICATE_ACCESSIBLE_SOURCE`和`UNRESOLVED`。检查器不得写数据库、Manifest 或媒体文件；迁移工作台、普通媒体库导入和后续自动化必须调用同一实现。
3. **一次性增加纯新增数据库 schema**：在第 2 步的数据模型经测试稳定后，再用单个前向版本保存包档位、导出／目标相对来源、解析快照与哈希令牌、接管证据、候选身份分类和自动接管／自动激活授权。旧会话和旧候选使用保守默认值；完成旧库升级、备份恢复和约束测试，避免为每个子功能连续升级 schema。
4. **先交付`CORE_CATALOG`端到端垂直闭环**：升级可移植包格式、required payload、身份账本过滤、导出／检查／空库导入／非空库合并、包列表、审计和 Web 工作台；同时兼容读取旧 format v1/v2 为 Gallery 辅助包。优先完成此项是因为它与媒体来源无关、风险最低，并能尽早兑现“Gallery 全异常也不阻断核心目录迁移”。
5. **完成 MT-03 的安全人工导入基础闭环（暂不分叉）**：把共享分类接入媒体库发现，先实现`UNCLAIMED`完整 Manifest 的“复验令牌 → 创建 DRAFT／来源 → 按精确路径扫描并认领 Item UUID → Pull”顺序和可恢复幂等语义；再接入来源移动、迁移 Claim、退役／跨类型及局部冲突的明确入口。该步骤先验证后续接管和自动化都会复用的最关键写路径。
6. **完成 MT-02 的来源重新定位、部分重建与人工接管**：在已验证的身份检查和扫描认领能力上，实现迁移工作台`EXACT`／唯一迁移解析、`ADOPT`预览与证据失效、READY 项部分重建和 owner continuity 完成门禁；随后加入有界批量操作及 Web 状态展示。
7. **叠加默认关闭的自动接管与独立自动激活授权**：只有人工接管闭环及并发复验稳定后，才允许字节级完全匹配、全局唯一、Claim 闭合的项自动认领；自动激活保持独立授权和既有激活门禁。此步骤不能引入第二套检查或扫描路径。
8. **实现 MT-03 独立副本分叉**：最后接入高风险文件写入，使用已稳定的预览令牌、冲突分类和原子 Manifest 写回；分叉写回与重新发现／导入仍是两个可恢复动作，并覆盖只读来源、`.bak`及中断恢复测试。
9. **最后开放 MT-01 TRUSTED 目录 Manifest 自动化**：自动化只编排前述已经验证的共享检查、显式导入、派生任务和激活门禁；`MANUAL`／`ASSISTED`行为不变。先以单项失败不阻断同批其他候选、持久化进度和稳定问题码为验收重点，再做真实大批量媒体库演练。

每个垂直阶段都同步完成 Go／SQLite／GraphQL／React 定向测试、开发状态记录和临时媒体目录演练，不把所有 UI、测试或文档拖到最后集中补齐。只有第 9 步完成且全套回归通过后，才进入正式业务库备份、迁移和增量部署。
