# CGM 视频硬件加速实施方案

> 状态：HA-01至HA-03已提交并部署；HA-03仍待真实业务验收；正式服务保持SOFTWARE
> 记录日期：2026-10-01
> 当前范围：Linux原生与Docker；Windows原生继续延期
> 关联决策：[按需渐进视频播放](../architecture/PROGRESSIVE_VIDEO_PLAYBACK_2026-09-30.md)

## 1. 业务证据与结论

“麻花麻花酱－赛博修女”存档内测试视频为2160×3840、30fps、HEVC Main 8-bit、AAC、124.2秒，输入视频码率约14.43Mbps。正式服务日志显示播放请求8ms、转码槽等待0ms、容量检查1ms、存档成员打开与安全证明1ms，首个4秒HLS片段在6.621秒发布；FFmpeg长期只有约0.85～0.99倍实时速度，约25fps，低于源视频30fps，因此持续播放必然耗尽缓冲。

存档成员约216MiB，完整只读流出测试为0.329秒／655MiB/s；媒体盘读取抽样约396～410MiB/s，而输入只需约1.8MiB/s。存档定位可见开销约占首片段时间0.015%，持续Range桥接仍需补充字节与耗时指标，但不是本次主要瓶颈。主要成本是4K HEVC软件解码、2160×3840到1080×1920缩放及`libx264`编码。

当前宿主机Intel UHD 630和NVIDIA GTX 1050 Mobile设备均可由正式CGM用户访问；FFmpeg的VAAPI及NVENC最小编码烟测通过。相同业务成员的12秒指示性基准中，近似软件管线约1.20倍实时，NVDEC＋CUDA缩放＋NVENC约1.61倍；首个4秒HLS片段由约4.25秒降至约1.60秒。未调校NVENC片段体积接近软件输出5倍，初步限码后仍约2.8倍，因此硬件路径上线前必须先完成质量、码率和VBV校准，不能直接采用基准命令。

## 2. 不可改变的业务与安全边界

1. CPU软件路径继续作为正确性基线；GPU不可用不能影响图片业务、DIRECT、REMUX或已有代理播放。
2. 播放选择仍为DIRECT优先、已就绪MP4优先、REMUX沿用完整MP4路径，只有确需转码才选择硬件管线。
3. Gallery卡片、Scrubber和未打开的视频不得触发探测、硬件初始化或转码。
4. 存档仍只允许已经严格证明可直读的成员进入播放转码；硬件回退不得绕过来源、身份、revision、可见性或容量门禁，不可直读成员不得临时提取播放。
5. 原媒体只读；所有临时片段与代理只写CGM缓存。日志不得记录媒体路径、标题、会话令牌或观看位置。
6. H.264/AAC、最高1080p且不放大、确定性主视频／音频轨、旋转及HDR到SDR语义不变；首版不增加多码率、字幕、多轨、播放历史或Dolby Vision专用流程。
7. 硬件设置属于本机运行能力，不进入Manifest或可移植迁移包。完整灾难恢复可保留设置，但恢复到不同宿主机后必须重新探测，`AUTO`不得盲用旧设备路径。
8. 硬件会话和显存有独立上限；不能把GPU任务视为零成本，也不能直接放大现有`worker_count`。

## 3. 管线与缓存设计

新增单一`VideoTranscodePlanner`供渐进HLS和完整MP4代理共用。输入为持久技术元数据、播放方案、本机硬件能力和本机偏好；输出明确包含输入解码、帧所在内存域、缩放／旋转／色调映射滤镜、编码器、码率控制、软件回退资格及有效Profile。

首批支持模式：

- `SOFTWARE`：现有软件解码、CPU滤镜、`libx264`；始终可回退。
- `AUTO`：只选择本次启动已通过完整烟测且适合当前编码／位深／滤镜的后端。
- `NVENC`：优先NVDEC→CUDA滤镜→NVENC；任一必需环节不支持时按策略回退软件，而不是伪称全硬件。
- `VAAPI`：第二个生产后端，覆盖Intel/AMD Linux设备；QSV先作为诊断候选，待滤镜和驱动矩阵验证后再决定是否成为独立生产后端。

硬件与软件输出不能错误共用Profile。Profile至少包含规划器版本、有效后端、完整／部分硬件模式、解码器、滤镜策略、编码器、码率控制、尺寸、关键帧／片段规则、HDR／旋转策略及FFmpeg版本。硬件失败后若改用软件，必须切换到软件有效Profile再发布；不得把软件产物登记为硬件Profile。HLS成功后仍只流复制提升为现有`VIDEO_PLAYBACK`增强MP4，继续受容量、LRU、内容失效和清理闭环管理，不增加观看身份或Manifest数据。

## 4. 分阶段优先级

### HA-01 只读能力诊断（最高优先级）

部署状态：2026-10-01已实现并部署。产品启动后在有界后台任务中完成能力枚举、设备访问检查及合成帧上传／缩放／H.264编码烟测；管理设置页只读展示结果。正式服务返回`NVENC=AVAILABLE`、`VAAPI=AVAILABLE`、`QSV=SMOKE_TEST_FAILED`。烟测不会读取媒体，也不授予生产转码资格，实际播放命令保持不变。

- 枚举FFmpeg的hwaccel、解码器、编码器和必需滤镜，但“编译存在”不等于“运行可用”。
- 枚举Linux render节点与NVIDIA设备；只显示技术设备标识，不显示媒体路径。
- 对NVENC、VAAPI及候选QSV执行有界合成帧烟测，分别验证设备初始化、H.264编码以及后续所需的HEVC解码／缩放组合；超时或失败不阻断服务启动。
- Manage Settings只读展示`未编译／设备缺失／权限不足／烟测失败／可用`、设备、能力和最近探测时间；日志使用稳定事件码。
- 此阶段不改变任何FFmpeg播放命令、Profile、数据库schema或默认行为。

退出门禁：无GPU、无权限、错误设备、命令超时及成功设备均有测试；诊断失败时服务和软件播放正常。

### HA-02 本机设置与安全规划器

实现状态：2026-10-01已随`7beb411`提交并部署。schema v22只在`runtime_settings`增加模式、一次软件回退开关和设备技术标识；正式库升级后确认为`SOFTWARE`、允许回退且未选择设备。完整备份因包含数据库而保留这三项，可移植迁移包与Manifest不包含它们。Manage Settings只允许保存本次启动诊断为`AVAILABLE`的NVENC／VAAPI设备，QSV不进入生产选项。

共用纯规划器现已覆盖HLS与完整MP4工作负载，`AUTO`确定性优先NVENC、其次VAAPI，并同时核对当前输入编码、8-bit像素格式、旋转／HDR边界和探测到的解码器能力；不满足时按本机开关形成软件计划或不可执行计划。有效Profile包含工作负载、请求／实际后端、设备、解码器、滤镜、编码器和码率策略，避免软硬件或HLS／MP4误共用缓存。HA-02不会把计划接入现有FFmpeg命令，实际播放仍为软件路径。

- 增加本机`SOFTWARE | AUTO | NVENC | VAAPI`偏好、硬件失败是否允许一次软件回退及设备选择；默认`SOFTWARE`，升级后绝不自动改变既有输出。
- 设置只接受服务端已探测设备标识，禁止把任意命令参数或未经验证的路径传给FFmpeg。
- 若持久化需要schema v22，只修改本机运行设置，并同步备份／恢复与可移植迁移“不导出本机硬件设置”的测试。
- 实现共用规划器和版本化Profile，但暂不启用硬件执行。

退出门禁：各种元数据、旋转、HDR、位深和后端组合得到确定性计划；设置并发更新和迁移边界通过。

### HA-03 NVIDIA渐进HLS首条生产链路

实现状态（2026-10-02）：上述实现已随`3805cc8d105578382a861ab381860297e48cf61f`提交并以`SOFTWARE`设置部署。冻结的执行计划已接入渐进HLS，严格接受`nvidiaN`设备标识，并为H.264／HEVC 8-bit输入构造NVDEC→CUDA缩放→NVENC命令；软件与NVENC使用隔离的v2 HLS Profile。VAAPI在本阶段只可规划，允许回退时在执行前改用软件，否则显式拒绝。会话创建后冻结执行计划，Seek重启不会在中途切换后端；日志记录实际后端及首片段耗时／字节，不记录路径。端到端门禁曾发现NVENC只接受通用`force_key_frames`但未把它们编码为IDR，36秒输入只形成2段；现已加入本机能力确认过的`forced-idr=1`，恢复每4秒独立片段，完整片段校验和MP4提升均通过。会话响应携带非敏感的实际后端；硬件FFmpeg运行失败使用独立`VIDEO_HARDWARE_HLS_FAILED`，无论状态轮询还是hls.js错误谁先到达，前端都会释放会话、明确提示且不得静默启动软件MP4代理。只有用户重试或切换`SOFTWARE`才能改变执行；经技术错误分类、临时清理、Profile切换后自动回退一次仍属于HA-04。

真实业务样本校准使用“麻花麻花酱－赛博修女”存档中最小的2160×3840、30fps、HEVC Main 8-bit视频，只读提取到临时目录后对相同12秒区间比较。当前软件HLS约9.68秒、峰值RSS约700MiB、输出5,795,100字节；最终NVENC候选`p4/hq + VBR CQ25 + 3M/5M/10M VBV`约2.21秒、峰值RSS约373MiB、输出7,106,964字节，即速度约4.4倍、体积约增加22.6%。缩放参考的SSIM为软件0.991787、NVENC 0.993006。该结果证明参数可进入业务验收，不等于主观画质、真实存档Range端到端、浏览器连续播放／拖动和取消均已验收。

- 仅为明确支持的HEVC/H.264 8-bit输入启用NVDEC→CUDA缩放→NVENC H.264；不支持的Profile、像素格式、旋转或HDR先回退软件。
- 以真实图库校准NVENC VBR/CQ、最大码率和VBV，使4秒片段体积、缓存总量和主观画质处于已接受范围；不能只按速度上线。
- 保留当前一个播放转码槽；会话取消、Seek重启、认证、存档Range输入、临时清理和HLS→MP4提升语义不变。
- 日志记录实际解码／滤镜／编码后端、首片段耗时、速度、输出字节和回退事件，不记录命令或路径。

退出门禁：真实存档和目录视频冷启动、连续播放、随机Seek及取消通过；持续速度稳定高于1倍实时，首片段有可证明改善，码率／画质经人工确认，来源hash／mtime／size不变。

### HA-04 一次性软件回退与完整MP4统一

- 设备初始化、驱动丢失、硬件不支持等技术错误允许同一请求清理临时文件后回退软件一次；鉴权、来源安全、revision、容量及磁盘错误禁止回退。
- 对连续失败设备实施本次运行期短暂熔断，避免每个播放请求重复失败；恢复只通过到期重测或显式重新诊断。
- 后台完整MP4代理接入同一规划器和硬件链路；避免HLS和后台任务同时生成同一Item的两份代理。

退出门禁：硬件失败→清理→软件成功、双失败、取消竞态、Profile切换、缓存登记和服务重启均有回归。

### HA-05 HLS供给优化

- 评估首片段2秒／后续4秒，或只公布已完成片段的更新式playlist，避免当前完整VOD列表让hls.js长时间请求未来片段。
- 保留显式随机Seek重启能力，不因动态playlist恢复持久观看位置。
- 调整hls.js缓冲目标、片段请求超时与服务端等待语义，避免用户释放会话后的取消被误记为真正转码错误。

本阶段必须在硬件速度稳定后实施；它不能替代“编码速度低于实时”的根本修复。

### HA-06 VAAPI／Intel与设备调度

- 增加VAAPI完整管线；再根据实际iHD／QSV能力决定是否提供独立QSV模式。不同设备、驱动和10-bit/HDR能力必须分别烟测。
- 拆分CPU与每块GPU的会话槽，前台HLS优先于Poster、动画预览和后台代理。初始每GPU仍为1，只有压力测试后才允许提高。
- 后台显示排队数、运行后端、实际速度、回退和熔断原因；后续再接入CPU／内存／I/O／显存自适应，不与首版硬件链路同时扩大复杂度。

## 5. 验收与部署基线

- 单元：能力解析、命令白名单、规划器、Profile、码率参数、回退分类和熔断。
- 集成：合成H.264／HEVC、横竖屏、8／10-bit、旋转、HDR、无音频及双音轨；无设备环境仍完整通过软件基线。
- 存档：安全Copy成员硬件播放、压缩／加密／布局未知继续拒绝，Range桥接读取指标不泄漏路径。
- 浏览器：首帧、24秒缓冲、连续播放、随机Seek、切换媒体、关闭Lightbox和重复冷／热播放。
- 性能：记录首片段p50/p95、持续倍速、CPU、RSS、GPU利用率、显存、输入／输出字节和缓存增长；与同一源的软件基准对照。
- 部署：每个改变实际转码行为的阶段独立提交、构建、备份和增量部署；先以`SOFTWARE`启动复核，再由所有者显式选择硬件模式。Docker另行验证设备映射和权限，不因原生通过而宣称容器通过。
