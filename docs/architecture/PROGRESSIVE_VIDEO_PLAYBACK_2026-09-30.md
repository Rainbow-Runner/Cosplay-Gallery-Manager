# 按需渐进视频播放决策

状态：所有者已于2026-09-30授权实施；2026-10-01已提交并部署本机，合成视频回归通过，真实4K业务验收待执行。

业务依据：实际两个4K HEVC视频时长85/119.4秒，完整MP4代理生成耗时84.082/125.362秒，冷启动等待不可接受。先增加阶段耗时和FFmpeg技术进度，再实施单清晰度HLS。Storyboard与硬件加速不作为本次前置条件。

## 本次决策

- 兼容原件DIRECT和已生成MP4继续优先。冷缓存视频通过独立的认证REST会话入口申请HLS，不同时提交原MP4任务。
- 单一最高1080p、不放大，H.264 veryfast / CRF20、AAC；编码预设仅为渐进路径变快，保持原画质参数。软件转码与已有MP4生成共享一个CPU播放转码槽。
- 首版采用4秒MPEG-TS独立片段及服务端生成的完整VOD播放列表，便于从任意片段起点重新生成；只有完整写入并原子改名的片段可返回，尚未生成的请求有界等待。此项替代第三阶段旧草案的fMP4/event选择，避免Seek重启后初始化片段依赖。浏览器优先原生HLS，否则使用本地打包的hls.js。
- 相同所有者登录Session、item/revision/profile复用同一生成会话。会话只在内存中，令牌不作为长期媒体身份；逐请求复核登录、可见性、来源及内容版本，空闲取消、维护模式和进程关闭均清理。
- 临时会话保留已生成片段以便当前会话回看；从头完整完成后，以流复制方式封装为既有VIDEO_PLAYBACK增强MP4缓存。跨会话复播走MP4；若随机拖动导致片段不完整，暂不提升缓存。旧MP4仍可直接复用。
- 以上完整缓存复用现有数据库、LRU、失效和迁移边界，无须新增bundle表或schema。临时HLS整体容量独立有界，并与已有ENHANCED总量、磁盘余量共同检查；过期会话及应用重启后识别出的会话目录整体回收。禁止扫描或删除未知目录。
- 存档只有已证明可直读成员允许使用私有Range输入，无法直读不临时提取；目录视频也接入同一渐进生成器。原媒体不修改。
- 阶段日志记录排队、来源证明、FFmpeg、缓存落盘/登记、首段、取消和清理；FFmpeg仅保留技术进度，不记录命令、路径、token、标题或观看历史。解码/滤镜/编码属于同一FFmpeg流水线，不伪造不可独立测量的分阶段耗时。
- HLS失败允许前端一次回退完整MP4，必须先释放HLS占用；鉴权失效、结构/来源安全错误不得回退绕过。关闭播放器释放会话，服务端空闲超时仍为兜底。

## 验证范围

先覆盖进度解析/日志、单槽、冷启动首段早于完成、Seek未生成片段、会话复用与关闭、认证/旧版本拒绝、压缩存档拒绝、磁盘不足、启动清理和MP4提升，再验证前端播放/销毁/回退。真实浏览器、HEVC首段和速度以实际测试为准，不承诺固定秒数。按需缓存不进入Manifest/迁移包。

参考：本机Stash `pkg/ffmpeg/stream_segmented.go`，Jellyfin `DynamicHlsController`；[FFmpeg HLS协议说明](https://ffmpeg.org/ffmpeg-formats.html#hls)、[hls.js API](https://hlsjs.video-dev.org/api-docs/hls.js.hls)。
