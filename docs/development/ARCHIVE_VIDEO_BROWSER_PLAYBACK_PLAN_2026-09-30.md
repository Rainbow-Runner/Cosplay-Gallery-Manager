# 存档视频浏览器播放方案修订（2026-09-30）

> 状态：所有者已确认编码文件头有界解码，以及仅对已安全证明可直读的存档视频按需 Remux／转码并使用可回收缓存；本地源码已实现，尚未提交或部署。播放请求仍不允许临时提取无法直读的存档成员。
> 上游边界：[存档视频决策记录](../architecture/MULTI_ENTITY_AND_ARCHIVE_VIDEO.md)、[视频第一／二阶段](VIDEO_PROCESSING_PHASE_1_2_PLAN_2026-08-15.md)、[第三阶段条件规划](VIDEO_PROCESSING_PHASE_3_PLAN_2026-08-15.md)。

## 1. 问题与目标

当前 7z 直接成员定位器只接受未编码的 `0x01 Header`；遇到 `0x17 EncodedHeader` 即返回 `ARCHIVE_VIDEO_DIRECT_UNAVAILABLE`。实际业务存档“麻花麻花酱－赛博修女”完整校验通过，90 个文件采用独立 Copy 存储，4 个 MP4 视频成员本身没有压缩，但存档使用编码文件头。因此后台能临时提取成员完成 FFprobe 和 Poster，浏览器播放却无法取得经过证明的成员 Range。四个视频另为 2160×3840 HEVC/AAC，即使解除文件头阻断，仍不符合当前 CGM 的通用浏览器 H.264/AAC 直放基线。

目标是**解除编码文件头这个一刀切条件**，而不是放松成员安全证明，也不是把 7z 一律视作可零提取读取。7z 格式将 `0x17` 定义为 EncodedHeader 的 StreamsInfo，与成员数据流的编码方法分开；实现必须分别验证两者。参考 [7-Zip 官方格式说明](https://github.com/ip7z/7zip/blob/main/DOC/7zFormat.txt)。

## 2. 更新后的能力判定

| 文件头 | 视频成员 | 浏览器编码 | 结果 |
| --- | --- | --- | --- |
| 明文或可安全解码的编码文件头 | 独立 Copy 且字节区间可证明 | 保守直放矩阵内 | 认证 Range 直放 |
| 明文或可安全解码的编码文件头 | 独立 Copy 且字节区间可证明 | 需 Remux／转码 | 用户打开时排队生成 MP4 兼容代理，使用可回收增强缓存 |
| 文件头加密、解码超限、复杂编码图或证明失败 | 任意 | 任意 | 拒绝直读；现有后台探测／Poster临时输入兜底不自动变为播放权限 |
| 任意 | 压缩、加密、Solid 共享流、危险成员或位置不可证明 | 任意 | 拒绝零提取播放；不把普通解压流伪装成可随机 Range 的原视频 |

“文件头编码”从最终拒绝原因改为**进入受限文件头解码与证明流程**；结果仍可因不支持的头部编码器、加密、资源超限或无效结构而拒绝。播放能力不足不阻断整个 Gallery 激活。

## 3. 有界 7z 文件头解码与成员证明

1. 先完成原有 Session／Gallery／Item 授权、当前来源证据复核，打开一个不跟随符号链接的固定存档描述符；之后的头部读取和成员 Range 都使用这个描述符。浏览器不得获得绝对路径、内部偏移或任务私有地址；未来若有兼容代理，FFmpeg 只能使用短期内部 loopback URL，不获得来源物理路径或偏移。
2. 验证签名头和 NextHeader 的偏移、长度与 CRC。`0x01` 沿用当前明文解析；`0x17` 只接受明确列入白名单、可有界解码的**头部** coder 组合，先验证 PackedStreams／HeaderInfo 的边界、大小、校验，再得到规范的 `0x01` Header。初版限定单层、单一独立头部流；AES、密码、BCJ／复杂多输入输出图、递归 EncodedHeader 及未知 coder 一律拒绝。是否纳入 LZMA 或 LZMA2 以真实样本和库能力测试为准，不预设所有编码头都可读。
3. 对压缩后的头部字节、解码后的头部字节、总元数据读取量、条目数、CPU时间和内存分别设置预算；解码时限与请求 context 绑定。沿用当前 16 MiB 默认／64 MiB 合法值硬上限的头部安全模型，不能仅检查压缩前大小而放任解码膨胀。过大或取消立即停止，不能回退成无限制全存档解析。
4. 将解码后的 Header 交给现有严格验证：文件名规范化、重复／穿越／链接／特殊文件、PackInfo、Coder、SubStream、CRC、成员数量及总大小必须一致。只对目标成员是独立 Copy、非加密、非 Solid、范围不越界且无重叠时返回只读 SectionReader。文件头被压缩不妨碍视频成员仍为 Copy；**不能**用 `7z l` 显示的 `Method=Copy` 代替 CGM 自身对偏移和布局的证明。
5. 初版每次打开成员重新用当前描述符证明，不把偏移写进产品库、Manifest、迁移包或跨请求的持久缓存。若真实 Range 性能证明重复解码成为瓶颈，再设计仅会话内、绑定固定描述符／当前来源证据的有界证明缓存；同大小同 mtime 隐藏替换仍遵守现有显式深扫边界。

对 `sevenzip` 公共 Reader 可复用的**头部解码能力**作实现期评估，但不得依赖私有字段、反射或未经证明的 FileHeader→物理偏移推断；若公共 API 不足，维持项目自有的窄范围证明器。保留 ZIP Store／普通 TAR／明文 7z 的既有行为和失败码兼容性；新诊断应区分“头部编码器不支持”“头部解码超限／损坏”“成员压缩或布局不可直读”“浏览器编码不兼容”，前端仍只显示安全的双语说明，不泄漏路径。

## 4. 浏览器兼容与兼容代理的分界

- **已确认的设计基线**：先解除文件头阻断，再独立执行现有 H.264／AAC、像素格式、旋转与 HDR 直放判定。不能因为 Range 已可读取，就把 HEVC MP4 宣称为所有浏览器均能直放；也不以扩展名或 `FFprobe READY` 当作播放就绪。
- Jellyfin 按客户端能力给出直放、换封装／音频及视频转码原因；Stash 提供直放与按需／预生成转码。CGM 先借鉴**能力原因分层**，不导入其 Scene／设备／观看历史模型。HEVC 浏览器支持因设备和设置而异，首版仍按项目既有的保守共同基线处理。[Jellyfin 编码兼容文档](https://jellyfin.org/docs/general/clients/codec-support/)、[转码类型](https://jellyfin.org/docs/general/post-install/transcoding/)。
- **已获所有者授权的兼容代理**：仅对已经证明可直读的 Copy 成员，在用户实际打开时创建 `VIDEO_PLAYBACK` 兼容代理；非存档视频继续沿用相同的按需转码能力。FFmpeg 使用任务私有本机 Range 桥接，不持久提取原件；输出沿用 H.264/AAC MP4 ENHANCED 缓存、item UUID＋content revision＋profile 身份、空间预算、LRU、失效和认证资源端点。未知或压缩成员不自动获得播放提取权限。
- 大型 4K HEVC 完整 MP4 代理可能使首帧等待和 CPU／磁盘占用较高；先按单重任务并发上限、取消／重试及实测耗时验收。只有冷启动反复不能接受时，才按现有第三阶段 ADR 门槛考虑单清晰度 HLS；不照搬 Jellyfin 的多档自适应、GPU配置、字幕和会话历史。

## 5. 实施阶段、测试与数据影响

1. **头部解析原型（只读）**：用真实编码头 Copy 7z、明文头 Copy 7z、压缩成员及加密／复杂头样本复核 coder 白名单、CRC、边界、解码预算和成员偏移；增加变异／模糊测试与短读、取消、来源替换测试。与 7z 工具比较只作交叉校验，不能以其列表作为证明器的输入。必须确认本次“赛博修女”样本的头部 coder 并在安全条件下通过成员证明；否则不能把“编码文件头阻断已解除”标为完成，须如实报告具体剩余限制。
2. **认证直读接入**：沿用来源证据、权限和当前 revision 复核；验证 GET／HEAD、单／多 Range、206／416、ETag、Seek、两个并发请求及连接中断，不读取或复制整个视频。明文 7z／ZIP／TAR 回归不得退化；不支持的头部和危险成员继续稳定拒绝。
3. **兼容代理**：已实现安全直读成员的按需代理与既有增强缓存复用；未证明直读时状态与 Worker 双重拒绝，且不会调用临时提取接口。真实 7z 编码头和合成编码头 Copy 视频的只读定位／转码回归已通过。仍需验证任务幂等、4K HEVC→1080p H.264/AAC、并发与磁盘预算、代理清理、旧 revision 失效和路径保密。
4. **浏览器业务验收**：用可直读 H.264 样本在目标浏览器验证播放、拖动及复播；用本次 HEVC 存档确认头部阻断解除后进入 `TRANSCODE` 排队，最终播放，而非假称原件可直放。观察单次头部证明 I/O、耗时和内存；播放前后来源 hash、size、mtime 不变。全流程失败均保留 Poster 与 Gallery 可见性，不反向扩大激活阻断。

本次复用现有 `VIDEO_PLAYBACK` 与增强缓存，无新数据库 schema、Manifest 或可移植包字段。是否需要新表以实现持久化会话／HLS，只有以后满足第三阶段条件并另行 ADR 后决定。此文档本身不授权媒体扫描、数据库迁移或部署。
