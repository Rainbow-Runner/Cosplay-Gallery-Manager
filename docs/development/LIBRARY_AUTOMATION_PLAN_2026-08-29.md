# 媒体库自动化处理规划（2026-08-29）

## 目标

在现有人工校核链路之上增加媒体库级自动化，使成百上千个候选可以按既有发现、扫描、分类和激活规则批量收敛；人工流程继续保留，既有Gallery不因升级被自动改动。

## 已确认基线

- 每个媒体库独立选择`MANUAL`、`ASSISTED`或`TRUSTED`，迁移后默认为未持久化的`MANUAL`。
- `MANUAL`维持现有流程；`ASSISTED`可发现、创建DRAFT、扫描和应用明确授权的确定性建议，但不激活；`TRUSTED`可在相同准备步骤后尝试激活。
- 自动创建仍由发现规则的`auto_create_draft`开关决定；冲突、超限和非确定候选不自动导入。
- 默认内容分级只填补空值，不覆盖已有分级。启用自动激活时必须配置默认分级。
- 媒体分类建议只在用户显式启用后自动接受。
- 实体自动匹配只接受名称或Alias规范化后精确且唯一，并且恰好形成一组Coser与Character的情况；Work若存在必须同样唯一并约束Character。模糊、多候选、多Credit或不完整组合继续人工复核。
- 激活继续调用统一Gallery状态机，不绕过来源、超限、可展示媒体、标题、分级、Credit/Cast和未解决实体建议等阻断器。
- 每次执行持久化策略revision、数量摘要、状态和错误码，不记录媒体路径或候选名称。
- 自动化运行可重复：首轮派生资源尚未READY时保留DRAFT，后续运行重新检查并可安全激活。

## 数据和兼容性

schema v6新增：

- `library_automation_policies`：媒体库级策略、显式开关和乐观锁revision。
- `library_automation_runs`：策略不可变快照、队列/租约/心跳、批次游标、取消状态与数量审计。
- `library_automation_run_issues`：只保存运行、Gallery/来源技术ID、处理阶段和稳定错误码的分项失败，不保存标题、实体名称或路径。

迁移是纯新增。v5数据库升级前必须创建自动安全快照；不为既有媒体库插入策略，不修改Gallery、来源、Item、关系、分类、排除决定或Manifest。正式业务库迁移必须在独立备份后另行授权执行。

## 开发阶段

1. 策略/schema：完成schema v6、默认MANUAL、策略校验、revision保护和迁移回归。
2. 预览/执行：完成最近发现与DRAFT就绪数量预览；执行发现、自动DRAFT、扫描、默认分级、保守实体匹配、确定性分类和可选激活；保存运行摘要。
3. API/UI：GraphQL查询/保存/执行和管理审计；Libraries页提供中英双语策略、预览、运行与最近结果。
4. 批量运行强化：把长时间同步运行迁入持久化后台任务，增加批次游标、取消、恢复、并发租约、失败分项与计划触发。
5. 验收：覆盖升级快照、默认不启用、策略冲突、重复运行、扫描失败、建议歧义、激活阻断、万级候选性能和崩溃恢复。

## 当前实现状态

阶段1～4的本地代码和受影响测试已经完成。后台工作器每批最多处理25个Gallery，每项后持久化游标；同库只允许一个QUEUED/RUNNING任务，租约由心跳续期，退出时主动回队列，过期租约可由新进程接管。现有“自动扫描”全局开关会为已保存ASSISTED/TRUSTED策略的媒体库定期入队，同时继续对其ACTIVE来源执行对账。

阶段5已完成可重复的本地合成门禁：运行中取消在发现前终止；90毫秒测试租约可由独立心跳跨过原到期点；批次游标保存后模拟工作器丢失，过期租约由替代工作器接管并从下一项完成；固定4核下10,000个已发现且来源IN_SYNC的Draft以25项一批完成400批，处理约1.802秒，门槛45秒。该数据只衡量队列、租约、游标、策略和逐项进度开销，不代表真实文件系统扫描或媒体解码吞吐。真实大媒体库长扫描、操作系统强杀进程、服务重启接管和取消延迟仍需在schema v6部署后执行。schema v6尚未迁移正式部署数据库，当前已部署应用仍按schema v5运行。
